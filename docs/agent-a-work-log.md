## 3. 产品与核心技术决策

### 3.1 单主智能体小镇

首版结构：

- 1 个主智能体：林澄。
- 4 名脚本 NPC。
- 6 个公开地点。
- 1 个昼夜循环。
- 7 天压缩模拟。
- 后续进行 14 天真实运行观察。

核心原则：

- 主智能体可以提出 `ActionIntent`，但不能直接修改世界。
- 世界引擎检查前置条件、资源、地点、时间和冲突后，才提交正式事件与状态变化。
- 脚本 NPC 有日程、关系、地点、台词模板、事件反应和有限记忆槽，不拥有全量大模型。
- 导演系统只注册候选事件、优先级和约束，不替主智能体选择结果。
- 观察者只能查看公开投影和提交受审核留言。

### 3.2 记忆模式

当前记忆方案已经统一到 `docs/adr-memory-core.md`，但“统一”不等于所有角色共享一个记忆池：

- 主智能体使用按完整作用域隔离的 `memory_core`。
- 每条主智能体记忆必须带六个作用域维度：
  `tenant_id`、`world_id`、`user_id`、`character_id`、`surface`、`conversation_id`。
- 脚本 NPC 只使用世界状态中的最多 8 个有限记忆槽。
- NPC 记忆槽不得进入主智能体召回，也不得读取主智能体私密日记或思考。
- 所有记忆必须能追溯到正式事件或明确操作来源。
- 同一去重键重放不能重复写记忆或重复强化。
- 公开 Web 只展示安全摘要，不显示分数、权重、提示词、完整私密记忆或数据库字段。

后续 AI 不得重新采用旧的“QQ companion 与 AI School 共用记忆租户”方案；当前项目以 G1 冻结的 ADR 为准。

### 3.3 生产数据栈

- 本地开发：SQLite。
- 服务器权威数据库：PostgreSQL 18.6 Windows 版本，由 `embedded-postgres` 提供。
- 首版不部署 Redis，不采用 Docker。
- 调度使用 APScheduler，依靠幂等键和 PostgreSQL advisory lock 防止重复执行。
- 进程由 FastAPI 和 Windows 计划任务承载。
