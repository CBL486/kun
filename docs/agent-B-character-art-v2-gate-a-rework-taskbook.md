## 4. 新的基本原则

### 4.1 插画和游戏精灵必须分开

从本轮开始，角色资源分成两条轨道：

| 轨道 | 用途 | 要求 |
| --- | --- | --- |
| Illustration | 主视觉、角色卡、表情、宣传预览 | 可以用高分辨率、细节、抗锯齿，但必须与游戏精灵身份一致 |
| Runtime Sprite | 地图上的 64×96 四方向动作 | 必须原生像素、有限色板、二元 Alpha、固定基线 |

Gate A 的通过顺序必须是：

```text
先看 Runtime Sprite 在 48×72 是否成立
再看 96×144 放大预览是否仍然是像素画
最后才看 1024 Illustration 是否有气质
```

不能反过来先做漂亮立绘，再希望它自动变成游戏素材。

### 4.2 美术定位

目标不是“高细节角色海报”，而是：

> 安静叙事型现代像素 RPG 中的主角色。

关键词：

- 人物小，但身份清楚；
- 色块干净，但表情温柔；
- 轮廓有辨识度，但装饰克制；
- 能连续做七类动作，不靠大量发丝和粒子撑画面；
- 与当前 Map 48×48 建筑、道路、树木的密度匹配。

### 4.3 造型减法

必须保留：

- 深蓝色长发，但头发总量控制在肩宽 1.6 倍以内；
- 两侧鲸鳍发饰，作为唯一强识别符号；
- 海军蓝短外套；
- 冰白内搭；
- 一个鲸尾或波纹扣饰；
- 平底或低跟短靴；
- 青绿色眼睛。

必须删除或弱化：

- 珍珠链、金属网、星形挂饰、多层宝石；
- 大腿绑带；
- 蕾丝裙撑；
- 过厚的鞋底和高跟鞋；
- 发尾铺满整个画面的海报效果；
- 发光粒子、星点、水花背景；
- 与动作无关的长飘带。

目标轮廓：

```text
头部：约 24～28 px 高
身体总高：64～72 px
总宽：32～40 px
头身比：2.3～2.5
脚底：固定基线
```

### 4.4 技术规格

运行时精灵必须满足：

| 项目 | 规格 |
| --- | --- |
| 逻辑帧 | 64×96 RGBA |
| 运行时显示 | 48×72 |
| 有效颜色 | 16～24 色，含透明色 |
| Alpha | 只有 0 或 255，不允许半透明抗锯齿 |
| 描边 | 1 px 深色外轮廓，允许局部 2 px |
| 阴影 | 单一硬边椭圆或固定像素阴影 |
| 像素网格 | 所有边缘落在整数像素格 |
| 渐变 | 禁止 |
| 发光 | 禁止直接画在身体外缘 |
| 方向 | down、left、right、up |
| 文件 | PNG 源图、lossless WebP 运行时表 |

## 6. Gate A R1 验收矩阵

每个方向按以下顺序评分：

### 6.1 游戏尺寸优先

在 48×72 下检查：

- 能否看出是一个蓝鲸少女；
- 鳍状发饰是否还能作为识别点；
- 脸部是否还有眼睛和嘴，而不是肤色方块；
- 外套和内搭是否能分层；
- 脚是否能看出来；
- 与草地、道路、建筑是否区分；
- 是否像当前游戏中的角色，而不是网页缩略图。

任一项失败，直接淘汰该方向，不看 1024 大图。

### 6.2 像素纯度

- 有效颜色不超过 24；
- Alpha 只有 0/255；
- 没有渐变、抗锯齿、模糊、外发光；
- 没有 0.5 px 或非整数像素边缘；
- 没有从 1024 图直接重采样出来的彩边；
- 像素簇结构在 4× 放大后仍然清晰。

### 6.3 游戏适配

- 64×96 格子完整；
- 四方向都位于格子内；
- 脚底基线稳定；
- 角色主体不触边；
- 透明背景干净；
- 头身比例一致；
- 左右方向不是简单水平翻转。

### 6.4 角色身份

必须能同时看到：

- 深蓝长发；
- 两侧青绿鳍饰；
- 海军蓝外套；
- 冰白内搭；
- 青绿眼睛；
- 一个鲸尾/波纹扣饰。

如果删掉任意三件装饰后角色仍然像“普通蓝发动漫少女”，说明身份设计不成立。
