# B11 安全、失败与成本压力矩阵

状态：已通过 A 复审

日期：2026-11-01

适用 schema：`rpg_orm` version 4

## 1. 成本模型

压力矩阵使用五个互不叠加的预算日：

| 场景 | 预算日 | 结论 |
| --- | --- | --- |
| 正常日 | 2026-11-01 | 5 次调用，成本 0.048 CNY |
| 异常日 | 2026-11-02 | 2 次接受，8 次被硬上限阻断 |
| 长对话 | 2026-11-03 | 4 次接受，16 次阻断 |
| 连续重试 | 2026-11-04 | 8 个可计费尝试，2 个逻辑请求阻断 |
| 并发突发 | 2026-11-05 | 8 次接受，12 次阻断 |

每个预算日成本均不超过 `0.10 CNY`。五个场景在汇总报告中保留独立日期，不能把不同
模拟场景相加误判为同一真实日消费。

机器报告：

```text
docs/b11-cost-report.json
```

## 2. 成本归因

`llm_cost_attributions` 记录：

```text
usage_id
budget_date
event_id
character_id
interface
```

报告支持按日期、事件、角色和接口聚合。报告总额必须等于所有 mock bill 行之和。

## 3. 限流

`SlidingWindowRateLimiter` 提供线程安全、按 key 隔离的滑动窗口：

- 超过窗口限额返回 `allowed=false`；
- 返回 `retry_after_seconds`；
- 并发请求不会超过限额；
- 窗口结束后自动恢复。

B12 可在 API 网关和反向代理层复用相同限流参数。

## 4. 人工确认

`ManualConfirmationGate` 用于高风险动作：

- 默认状态 `pending`；
- pending/rejected 时执行回调会被阻断；
- 只有人工 reviewer 明确 approve 后才能执行；
- 同一 operation 的确认理由不能冲突；
- 不保存高风险正文，只保存操作 ID 和理由码。

## 5. 失败场景矩阵

| 风险 | 行为 | 验收 |
| --- | --- | --- |
| 数据库不可用 | `/ready` 失败；世界事务整体回滚 | B4/B6 测试 |
| 模型超时/网络失败 | 同请求重试一次，随后规则模式 | B9 测试 |
| 模型非法 JSON/缺少 choices | 不重试，规则模式，不产生 usage | B9 测试 |
| 审核拒绝 | 丢弃模型文本，返回安全模板 | B9 测试 |
| 审核超时/不可用 | 失败关闭，不泄漏未审核内容 | B9 测试 |
| 预算上限 | 预检阻断 provider 调用 | B9/B11 测试 |
| 熔断打开 | 冷却期直接规则模式 | B9 测试 |
| 任务积压 | 优先级领取、租约上限和 backlog 可观察 | B8/B11 测试 |
| 并发调用 | 预算锁串行核账，provider 调用不超限 | B9/B11 测试 |
| 高风险发布 | 必须人工确认，pending/rejected 不执行 | B11 测试 |
| Prompt 注入 | 质量门禁报告 `prompt_injection` | B10 测试 |
| 事件/关系部分写入 | 单事务或幂等对账 | B4 测试 |

## 6. 安全边界

- 不读取真实 API Key、生产数据库或真实用户内容；
- 测试只使用合成 ID、mock provider、mock reviewer 和临时数据库；
- 成本报告和失败报告不保存完整 prompt、原始响应或私密记忆；
- 不执行服务器限流、计划任务、代理或部署操作；
- 真实价格、供应商幂等能力和审核 SLA 仍需 A 在 staging 确认。
